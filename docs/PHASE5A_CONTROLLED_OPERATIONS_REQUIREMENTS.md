Operations only needs to configure supported restricted entry points, without redeveloping SAFE50 or V6. Never replace registration with direct production CLI execution, database edits, or reuse of the SAFE50 release.

   English: Register a new V6 release. Check all five before-SHAs and absence of four new modules and the original image; stop on drift. After regression/review gates, coordinate locks, back up and replace restricted files, recover every changed file on failure, and verify after-SHAs. The current single-file four-operation executor does not provide the multi-file transaction guarantee this proposal requires.

   English: A separate isolated internal-QA release may first add only v6_outreach.py, v6_bestseller_evidence.py, controlled_v6_test.py and the hash-pinned original image, reusing existing bd_sender MIME/TLS helpers. Do not replace the customer sender, resume tasks, or change global SMTP=0. Provide a dedicated restricted test operation under the authorized operations identity, with an explicit operation-only internal SMTP exception and latest single-recipient local policy outside Git. Forbid arbitrary commands/paths. Send at most one per variant, persist unique test_run_id/template_id audits, never auto-retry ambiguous outcomes, and return Message-ID, timestamps and SMTP acceptance. Actual registration/validation is still required; this document does not bypass the global freeze.
