# PHASE 5A 最小正式接入要求 / Minimum supported operations requirements

中文：这是未执行的配置请求，非新权限、非部署脚本，也没有声称已交给 WorkBuddy。Codex 继续负责发布；只需运维方配置正式受限入口，无须重新开发 SAFE50 或 V6。不得以直接运行生产 CLI、修改数据库或复用 SAFE50 release 代替登记。

English: This is an unexecuted configuration request, not a permission grant or deployment script; delivery to WorkBuddy is not claimed. Codex retains release ownership. Operations only needs to configure supported restricted entry points, without redeveloping SAFE50 or V6. Never replace registration with direct production CLI execution, database edits, or reuse of the SAFE50 release.

1. 中文：登记新的 V6 release，核对 manifest 的四个 before-SHA 及三个新文件不存在；任一漂移立即停止。通过回归和审查后，在运行锁保护下逐文件备份并受控替换，失败恢复全部变更，校验 after-SHA。当前四操作单文件执行器不具备本提案需要的多文件事务保证，不应直接使用。
   English: Register a new V6 release. Check all four before-SHAs and absence of three new files; stop on drift. After regression/review gates, coordinate locks, back up and replace restricted files, recover every changed file on failure, and verify after-SHAs. The current single-file four-operation executor does not provide the multi-file transaction guarantee this proposal requires.
2. 中文：可以先登记只用于内部 QA 的隔离发布，只新增 v6_outreach.py 和 controlled_v6_test.py，复用既有 bd_sender MIME/TLS 辅助函数；不替换客户发送器、不恢复发送任务、不修改全局 SMTP=0。必须在受权运维身份下提供专门试发操作、明确仅此操作的内部 SMTP 例外，并安装最新单一白名单本地策略（不进入 Git），禁止任意命令/路径。三版各最多一封，审计唯一 test_run_id/template_id，不自动重试模糊结果；返回 Message-ID、时间和 SMTP 接受状态。此方案仍需实际登记和验收，本文件不是绕过全局冻结的依据。
   English: A separate isolated internal-QA release may first add only v6_outreach.py and controlled_v6_test.py, reusing existing bd_sender MIME/TLS helpers. Do not replace the customer sender, resume tasks, or change global SMTP=0. Provide a dedicated restricted test operation under the authorized operations identity, with an explicit operation-only internal SMTP exception and latest single-recipient local policy outside Git. Forbid arbitrary commands/paths. Send at most one per variant, persist unique test_run_id/template_id audits, never auto-retry ambiguous outcomes, and return Message-ID, timestamps and SMTP acceptance. Actual registration/validation is still required; this document does not bypass the global freeze.
3. 中文：Gmail 需用户通过官方连接完成 OAuth，无需密码。只读查询目标三封的 INBOX/SPAM/所有邮件及原始 Authentication-Results（SPF/DKIM/DMARC、From 对齐），同时保留实际接收时间。工具如不返回原始头，则保持认证 UNKNOWN，不能用 DNS 配置或 SMTP accepted 代替。
   English: Gmail requires the user's official OAuth connection, without a password. Read the three messages' INBOX/SPAM/all-mail placement and original Authentication-Results, including SPF/DKIM/DMARC and From alignment, with reception times. If raw headers are unavailable, retain UNKNOWN; DNS configuration and SMTP acceptance are not receiver validation.
4. 中文：外部发送仍需邮寄地址和业务承诺证据、退订及抑制实测、正式 MX 控制探针、最新 SAFE 与资格只读报告。通过支持的自动化管理入口核实唯一 PreSend/Preflight/Authorization/Outreach，旧 deleted 任务不能靠数据库恢复。follow_up 保持关闭，不增加 Inventory。
   English: External sending still requires postal/business-claim evidence, unsubscribe/suppression tests, an official MX control probe, and current read-only SAFE/eligibility reports. Verify a unique PreSend/Preflight/Authorization/Outreach chain through supported automation management; never restore deleted tasks through database edits. Keep follow_up off and add no Inventory.
5. 中文：新客户策略默认缺失即禁发，人工核实证据需有引用和有效时间。阶段为 5/10/20/40 个组织/日，各次升级需至少 24 小时真实反馈。SMTP 异常形成持久停止记录；回滚不得删除发送历史、预留或停止审计。当前工程回归仍有失败，不允许批准完整 V6 发布。
   English: Missing customer policy blocks sending. Reviewed evidence requires references and freshness. Stages are 5/10/20/40 organizations/day, with at least 24 hours of real feedback before each increase. SMTP errors latch a durable halt. Rollback never deletes send history, reservations or halt audits. Current engineering regression failures still prohibit approval of the complete V6 release.
